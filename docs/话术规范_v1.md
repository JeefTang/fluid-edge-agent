## 〇、一句话原则（写文案前的自检）

> **让客户相信我们「专业」+「有真工程经验」+「能带来真价值」——靠事实，不靠形容词。**

三条可信度杠杆（每一段文案至少命中一条）：

| 杠杆 | 含义 | 做不到就删 |
|:---|:---|:---|
| **① 可验证的数字** | 有量纲、有口径、有出处（"实测 602.3 kW""节电率 26.7%（口径A）"） | 无出处的"大幅""显著" |
| **② 现场实证** | 真实项目、真实工况、真实工种语言（锅炉给水泵、矿井排水、干熄焦余热） | "赋能千行百业" |
| **③ 敢写边界** | 明确"做不到什么"，反而加分（只预警不下令、仿真不能替代标定） | 全知全能式表述 |

**四条行业通病，我们一律不写**：① 只讲 AI 不讲机理；② 只讲功能不讲收益；③ 只讲云不讲现场；④ 只讲"我们很强"不讲"你怎么验证"。

## 一、标语体系（直接可用）

**主标语（品牌线，固定）**
> 让风机、水泵、压缩机「**会诊断、会省电、会说话**」

**副标语（能力线）**
> 一台放在设备旁边的边缘盒子：**现场采集 · 本地推理 · 断网可用 · 数据不出场**

**一句话定位（电梯稿 / 名片背面）**
> 我们把十几年流体机械**节能改造与运行诊断的现场经验**，装进一台跑在设备旁的国产边缘盒子——
> 让泵、风机、压缩机自己**报健康、算能耗、说人话**。

**区别性定位（对同行的一句话）**
> 不是通用边缘平台，也不是节能计算器——**只做流体机械（泵 / 风机 / 压缩机）这一件事**。

**三段式价值主张**

| 对象 | 话术 |
|:---|:---|
| **对设备厂** | 整机从"卖设备"升级为"**卖设备 + 智能服务**"：出厂即带健康监测与能效报告，售后从"等故障"变成"提前告知"，服务可续费、可分成。 |
| **对终端用户** | **少停机、少耗电、少扯皮**：提前发现轴承/不平衡/不对中/汽蚀等隐患；能耗有据可查；节能量可复核、可存证。 |
| **对高校/合作方** | 一套**真实工业场景**的边缘智能实训底座（国产算力 + 真实机理 + 可复现链路），共建人才与实验室。 |

## 二、话术骨架（七段式，照着填不会错）

1. **我们是谁**——"我们是干流体设备节能改造出身的，不是从算法开始的。"
   （先讲工程出身，再讲 AI。顺序不能反。）
2. **解决什么**——三大痛点，用**设备科/设备部听得懂的话**讲（见 §三）。
3. **凭什么**——四重壁垒：**设备机理 + 现场失效经验 + 边缘推理 + 与节能测算同口径的算法**。
4. **怎么做**——一句话讲完五层链路：「传感器 → 本地特征提取 → 边缘 AI 诊断 → 智能体翻译成人话 → 看板/告警/工单」。
5. **哪里不一样**——**监测 × 能耗 × 节能确权** 的闭环（见 §四）。
6. **守什么边界**——三条硬约束照实说（见 §六）。
7. **怎么开始**——**先 PoC 后铺开**：选一台设备装盒 → 跑 4~8 周 → 出对比报告 → 再谈规模（见 §七）。

## 三、三大痛点话术（用行业语言）

| 痛点 | 客户的真实说法 | 我们的标准话术 |
|:---|:---|:---|
| **非计划停机** | "机泵没有备件，一停后面全停" | 泵/风机/压缩机常**无备机、串联在流程里**，一次非计划停机的代价远高于监测投入。我们用振动/电流/温度多信号融合，给出**健康度评分 + 故障类型 + 风险等级**，把"事后抢修"变成"提前检修"。 |
| **能耗偏高** | "知道费电，但不知道费在哪、能省多少" | 工况一变，能耗就说不清。我们做**工况识别 + 能效趋势 + 基线对比**，让"改不改、改多少"有实测依据，而不是拍脑袋。 |
| **售后靠人** | "老师傅越来越少，出了问题等厂家" | 老师傅的经验要沉淀成**7×24 在线的设备医生**：现场断网也能问、能答、能出检修建议。 |

**（加分项）第四条**——"**检修质量没人验证**"：检修完到底好没好？我们用**修前/修后同一口径的特征对比**给出结论，让检修闭环有据可依。

## 四、差异化话术：状态监测 × 能耗显示 × 节能确权

> **核心句：把设备健康和节能量，都变成能上桌分成的数据。**

- **① 状态监测**——振动 / 电流 / 温度 → 健康度、故障类型、剩余寿命。「别人有的，我们也有，是**能力基石**。」
- **② 能耗显示**——稳态实际功耗、能效趋势、与基线逐时对比。「我们的**老本行**，算法与『节能测算平台』**同口径**。」
- **③ 节能确权（差异化）**——基线管理 + 工况归一 + 节能量核算 + **可审计证据链**，直接服务 **EMC 分成、碳核算、节能审计**。

**为什么这个组合稀缺（三段论，可背）：**
1. 做**状态监测**的，多半不懂节能算法与 EMC 结算——"省了多少"算不明白；
2. 做**节能改造**的，多半没有设备侧采集——节能量靠估算，工况一变就扯皮；
3. 我们**两头都在**：设备机理 + 轴功率算法（同口径）+ 边缘本地采集 → 把"省了多少"变成**可复核、可存证、可分成**的数据。

## 五、对标提炼：国内头部厂商话术拆解与转化

> 语料来源：容知日新官网（设备智能运维领域领军者，2026-10 直连抓取）等国内头部厂商公开页面。
> 提炼 = 学**结构**（怎么建立信任），转化 = 换**立足点**（我们的现场与流体机专门性）。

### 5.1 头部厂商的信任构建套路（学什么）

| 套路 | 头部厂商原话（节选） | 我们要学的点 |
|:---|:---|:---|
| **先立身份** | "设备智能运维领域**领军者**""软硬一体的**全栈自研**" | 开头先给"我是谁、凭什么" |
| **数据说话** | "1400+ 工业企业""220,000+ 台套实时监测""46,000+ 故障闭环案例""4,300,000+ 份体检报告""240+ 监测设备类型" | **堆可核查的规模数字**建立规模信任 |
| **对标痛点** | 机泵四大痛点：点检难度大 / 采集数据单一 / 智能化不足 / 续航短 | 用**客户的痛点原话**开头，不用自己的功能开头 |
| **给台阶** | "多位一体监测 / 100+ 指标边缘计算 / 20+ 故障自动监测" | **量化能力**（几位一体、多少指标、多少故障类型） |
| **讲收益故事** | "从'救火队'到'预报员'""把问题解决在'抢救'之前""帮单台风机平均每年**多转 84 小时**""减少 **825 小时**非停""至今保持**零起**安全事故" | **收益要用"小时/万元/次"这种可换算的单位**，不用"提升效率" |
| **讲闭环** | "边缘报警→云端诊断→专家审核→现场巡检→故障下达→检修评估→案例闭环" | 把**流程闭环**写清楚，显示"不是卖个盒子" |
| **讲安全责任** | "高温高压、易燃易爆、有毒有害各类高危泵……至今零起安全事故" | 高危场景敢**背书**，是强信任点 |

### 5.2 我们的转化（换成我们的立足点）

| 维度 | 头部（云 + 大规模 + 广谱） | 我们（边缘 + 现场 + 专精流体机械） |
|:---|:---|:---|
| 身份 | 全栈自研的平台型领军企业 | **从现场长出来的流体机械专家**（先做改造，再做智能） |
| 规模 | 上千家客户、几十万台套 | **不吹规模，吹深度**："一台设备也能跑通，且跑的是真实工况" |
| 覆盖 | 电力/石化/冶金/水泥/煤炭/轨交全行业 | **只做泵 / 风机 / 压缩机**——越窄越专业 |
| 站位 | 云端诊断中心、专家团队 | **设备旁边**：断网可用、数据不出场、毫秒级本地闭环 |
| 收益口径 | 非停小时、事故率 | 非停小时 **+ 节电量/节能费**（我们的独门：EMC 可分成） |
| 信任来源 | 规模数字 | **真实项目 + 敢写边界 + 可复现的演示** |

> **话术模板（对客户说）：**
> "您说的这些，容知日新这类平台级公司做得很大——**但那是云端、广谱、大项目**的打法。
> 我们做的是另一件事：**在设备旁边放一个盒子**，现场就把健康度和能耗算清楚，**断网能用、数据不出厂**；
> 而且我们不只想告诉您'设备要坏了'——我们还能告诉您'**这次大修到底省了多少电、这笔钱怎么算、怎么分**'。
> 这个组合，目前做监测的和做节能的，各缺一头。"

### 5.3 可复用的"信任句式"（替换关键词即可）

- 「不看广告看**实测**：这台设备的输入功率是**现场电表标定**出来的，不是估的。」
- 「我们**先算清楚，再谈智能**——算法口径与我们的节能测算平台**完全一致**。」
- 「**先跑 4~8 周 PoC**，出**修前/修后对比报告**，数据不达标，您可以不继续。」
- 「**AI 只预警、不下令**；停机切泵必须人工确认——安全回路归设备既有的保护系统。」

## 六、边界话术（敢写边界 = 加分项）

三条硬约束，逐字对外：

1. **诊断模型层负责「判」**：故障类型 / 健康度 / 风险等级 / 寿命，只由模型输出。
2. **智能体层负责「说与做」**：只读取、编排、翻译，**不得自行推断故障**。
3. **不下高危指令**：停机 / 切泵只"建议并等待人工确认"，硬保护回路由设备既有安全系统负责。

补充声明（保持）：
- **仿真数据 ≠ 现场标定**：演示用机理仿真信号跑通算法链路，投产前**必须用现场实测基线替换阈值**。
- **数据合规**：现场数据本地处理、不出场。

> 写法要点：边界**放在显眼处**（不要藏进小字），并用"**所以我们只做…**"收尾，把限制写成专业。

### 8.1 用（加分）

### 8.2 不用 / 慎用（减分）
| 禁用 | 原因 | 替换 |
|:---|:---|:---|
| 最强 / 唯一 / 第一 / 全球领先 | 无法自证，反而掉信任 | 换具体事实（"只做泵/风机/压缩机"） |
| 颠覆 / 革命性 / 黑科技 | 工业客户反感 | 换"解决 XX 具体问题" |
| 赋能千行百业 / 一站式 | 空 | 换行业与场景名 |
| 100% 准确 / 零误报 | 做不到，且是事故隐患 | 换"误报可控、可人工复核、有置信度" |
| 秒级 / 一键 / 零门槛 | 夸大且不专业 | 换具体时延（"≤50 ms 边缘推理"） |
| AI 自动决策 / 代替人工 | 越权、危险 | 换"AI 预警 + 人工确认" |

### 8.3 数字表达规范
- 数字必须带**口径与单位**：写"节电率 **26.7%（口径A：只扣电机效率 95%）**"，不写"节电率 26.7%"。
- 预测类数字必须带**条件**：写"**实测 8000 h/年、0.35 元/kWh 条件下**，年省 45.0 万元"。
- 演示类数字必须带**标注**：写"演示数据，现场以实测标定为准"。

## 十、常见问答（客户一定会问，先备好）

**Q1：你们和容知日新这种大厂有什么区别？**
> 他们是云端的平台型公司，覆盖全行业、上规模；我们是**设备旁边的盒子**，只做流体机械，**数据不出厂、断网能用**，而且多了一层别人没有的：**节能量的可复核与可分成**。大项目找他们，**专精设备侧 + 节能闭环**找我们，也可以互补。

**Q2：数据上云吗？会泄密吗？**
> 默认**不出场**：采集、推理、存证都在盒子本地完成；要不要上行、上行什么，由您定。

**Q3：AI 会不会误报、乱报警？**
> 我们给的是**健康度 + 风险等级 + 置信度**，高风险才告警；**算法层只判、不执行**，告警可人工复核；投产前用您现场基线标定阈值。

**Q4：到底能省多少钱？**
> 得先测。我们**先跑 4~8 周 PoC**，用现场实测输入功率对比基线，出**节电量与节约金额**，口径与节能测算平台一致——**算得出来，才敢承诺**。

**Q5：会不会替我把设备停了？**
> 不会。**只建议、不下令**。停机/切泵必须您人工确认，安全保护归设备既有系统。
