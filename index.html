什么是工业边缘智能体？

一句话：装在设备旁的一台「边缘计算盒子」——采集、计算、判断都在设备旁边完成，断网可用、数据不出场。

🧩

是什么

一台国产边缘计算盒子（RK3576 · NPU），装在泵 / 风机 / 压缩机旁边，把「传感器采集 + 设备机理 + AI 推理」集于一体，让设备自己能「说话」。

🛠️

能干什么

① 健康诊断：振动 / 温度 / 声音 → 故障类型 + 风险等级；② 能耗显示：稳态实际功耗与能效趋势；③ 节能确权：节能量可复核、可存证。

💰

带来什么价值

对终端用户：少停机、少耗电、少扯皮；对设备厂：从「卖设备」升级为「卖设备 + 智能服务」，服务可续费、可分成。

🔧

怎么实现的

传感器采集 → 边缘盒子本地推理（≤50 ms）→ 智能体翻译成人话（结论 / 依据 / 建议 / 风险）。全程本地，数据不出场。

它解决什么问题

泵、风机、压缩机 7×24 在转，痛点就三个

机泵常没有备机、又串联在流程中间，一次非计划停机的代价，远高于监测的投入。这套系统从设备侧下手，不是从云端。

🛑

非计划停机

振动 / 电流 / 温度多信号融合，输出健康度评分 + 故障类型 + 风险等级，提前发现轴承、不平衡、不对中、松动隐患——把「事后抢修」变成「提前检修」。

⚡

能耗说不清

工况一变，能耗就说不清。做工况识别 + 能效趋势 + 基线对比，让「改不改、改多少」有实测依据，而不是拍脑袋。

🧰

老师傅越来越少、厂家响应慢。边缘盒子本地推理、断网可用，现场问一句答一句，把经验沉淀成 7×24 在线的「设备医生」。

整机从「卖设备」升级为「卖设备 + 智能服务」：出厂即带健康监测与能效报告，售后从「等故障」变成「提前告知」，服务可续费、可分成。

壁垒：设备机理 + 现场失效经验 + 边缘推理 + 与节能测算同口径的算法——做「设备专用」，不做通用平台。

差异化定位

状态监测 × 能耗显示 × 节能确权

市面上的「状态监测工业智能体」已经很多，但大多止步于报警与健康度。 真正稀缺的，是把能耗和节能确权接成一条闭环——这，就是我们的差异化。

🩺

① 状态监测

振动 / 电流 / 温度多信号 → 健康度评分、故障类型、剩余寿命。别人有的，我们也有，是能力基石。

⚡

② 能耗显示

稳态实际功耗、能效趋势、与基线逐时对比。我们的老本行，算法与「节能测算平台」同口径。

🔐

③ 节能确权 ·差异化

基线管理 + 工况归一 + 节能量核算 + 可审计证据链。为 EMC 分成、碳核算、节能审计提供“说得清”的数据。

节能确权怎么做

  1. 建基线：沉浀稳态工况库，形成可比对的能耗基线。
  2. 工况归一：把能耗折算到统一工况，排除产量 / 工况波动干扰。
  3. 算节能：实测输入功率 vs 基线，逐时 / 逐日核算节电量与节约金额。
  4. 存证：带时间戳的本地记录，可导出审计报表 → 直接服务分成与碳核算。

为什么这个组合稀缺

  • 做状态监测的，多半不懂节能算法与 EMC 结算——“省了多少”算不明白；
  • 做节能改造的，多半没有设备侧数据采集——节能量靠估算，工况一变就扯皮；
  • 我们两头都在：设备机理 + 轴功率算法（与测算平台同口径）+ 边缘本地采集。把“省了多少”变成可复核、可存证、可分成的数据。

把设备健康和节能量，都变成能上桌分成的数据。

技术选择说明

为什么这么做

每一个取舍，都是被现场条件逼出来的——先算清楚，再谈智能。

机理规则先于深度学习

现场真实失效样本稀缺（复现故障要停机），深度模型冷启动没数据；先用可解释规则 + 无监督检测顶上。

包络谱峰「突出度」作核心判别器

轴承缺陷呈窄带包络（峰极突出），汽蚀呈宽带（峰不突出）——只看总能量会把这俩混淆。

只用 numpy（无 scipy / sklearn）

边缘盒子上无重型依赖，特征维度 <20，便于后续 INT8 量化上 NPU。

仿真信号而非数据集

零数据依赖、开箱即跑、可复现；同时体现「设备机理」这一壁垒。

先算清楚，再谈智能

能效与节能量算法和《节能测算平台》共用一套口径，客户可以拿同一把尺子复核；口径不一致的「智能」，我们不做。

⚠️ 边界与声明 · 我们敢把界限写在这

  • 仿真数据：本页/仓库用机理仿真的振动信号演示算法链路，不能替代现场标定；所有阈值为演示值，投产前必须用现场实测基线替换。
  • 安全边界：系统只做「预警 + 建议 + 辅助决策」，不下发停机 / 切泵等控制指令；硬保护回路由设备既有安全系统负责。
