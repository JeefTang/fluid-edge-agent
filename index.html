差异化定位

状态监测 × 能耗显示 × 节能确权

市面上的「状态监测工业智能体」已经很多，但大多止步于报警与健康度。 真正稀缺的，是把能耗和节能确权接成一条闭环——这，就是我们的差异化。

🩺

① 状态监测

振动 / 电流 / 温度多信号 → 健康度评分、故障类型、剩余寿命。别人有的，我们也有，是能力基石。

⚡

② 能耗显示

稳态实际功耗、能效趋势、与基线逐时对比。我们的老本行，算法与「节能测算平台」同口径。

🔐

③ 节能确权 ·差异化

基线管理 + 工况归一 + 节能量核算 + 可审计证据链。为 EMC 分成、碳核算、节能审计提供“说得清”的数据。

节能确权怎么做

  1. 建基线：沉浀稳态工况库，形成可比对的能耗基线。
  2. 工况归一：把能耗折算到统一工况，排除产量 / 工况波动干扰。
  3. 算节能：实测输入功率 vs 基线，逐时 / 逐日核算节电量与节约金额。
  4. 存证：带时间戳的本地记录，可导出审计报表 → 直接服务分成与碳核算。

为什么这个组合稀缺

  • 做状态监测的，多半不懂节能算法与 EMC 结算——“省了多少”算不明白；
  • 做节能改造的，多半没有设备侧数据采集——节能量靠估算，工况一变就扯皮；
  • 我们两头都在：设备机理 + 轴功率算法（与测算平台同口径）+ 边缘本地采集。把“省了多少”变成可复核、可存证、可分成的数据。

把设备健康和节能量，都变成能上桌分成的数据。

  • 诊断模型层负责「判」：故障类型 / 健康度 / 风险等级 / 寿命，只由模型输出。

技术选择说明

为什么这么做

每一个取舍，都是被现场条件逼出来的。

机理规则先于深度学习

现场真实失效样本稀缺（复现故障要停机），深度模型冷启动没数据；先用可解释规则 + 无监督检测顶上。

包络谱峰「突出度」作核心判别器

轴承缺陷呈窄带包络（峰极突出），汽蚀呈宽带（峰不突出）——只看总能量会把这俩混淆。

只用 numpy（无 scipy / sklearn）

边缘盒子上无重型依赖，特征维度 <20，便于后续 INT8 量化上 NPU。

仿真信号而非数据集

零数据依赖、开箱即跑、可复现；同时体现「设备机理」这一壁垒。

⚠️ 边界与声明

  • 仿真数据：本页/仓库用机理仿真的振动信号演示算法链路，不能替代现场标定；所有阈值为演示值，投产前必须用现场实测基线替换。
  • 安全边界：系统只做「预警 + 建议 + 辅助决策」，不下发停机 / 切泵等控制指令；硬保护回路由设备既有安全系统负责。
